## نظرة عامة

طلابي هو تطبيق ويب كامل (Full-Stack) لإدارة مراكز التعليم. يهدف لتسهيل متابعة الطلاب أكاديميا وماليا مع توفير قناة تواصل مباشرة مع أولياء الأمور عبر واتساب.

### المميزات الأساسية
- واجهة عربية كاملة تدعم RTL
- نظام صلاحيات: معلم كامل الصلاحيات + مساعد بصلاحيات محددة
- إدارة الحضور عبر QR code
- نظام محفظة لتسوية المدفوعات مع الحصص والكتب
- تواصل مع الطلاب وأولياء الأمور عبر WhatsApp Business API
- استقبال رسائل واتساب واردة وربطها بالطلاب تلقائيا
- تقارير وإحصائيات شاملة
- تصدير CSV لجميع الجداول

## نظام الصلاحيات

### الأدوار

| الدور | الوصف |
|-------|-------|
| **معلم (teacher)** | صلاحية كاملة لكل شيء. يتجاوز جميع فحوصات الصلاحيات |
| **مساعد (assistant)** | صلاحية محددة وفقا لمصفوفة الصلاحيات المسندة إليه |

### صلاحيات المساعد

| الصلاحية | الصفحات المتيحة |
|----------|-----------------|
| `students` | الطلاب، طباعة QR code |
| `groups` | المجموعات، إدارة طلاب المجموعة |
| `sessions` | الحصص |
| `attendance` | الحضور |
| `payments` | المدفوعات، سجل المدفوعات |
| `exams` | الامتحانات، درجات الامتحانات |
| `books` | الكتب والحجوزات |
| `chat` | الشات وواتساب |

### آلية التحقق
1. **الواجهة الأمامية**: القائمة الجانبية تخفي الروابط غير المصرح بها للمساعد
2. **الخادم**: كل endpoint لديه middleware يتحقق من الصلاحية (`requirePermission`)
3. **المعلم** يتجاوز كل القيود تلقائيا

## الوحدات الوظيفية

### ١. المصادقة وإدارة الحسابات

**الصفحات:** `/login`، `/assistant-info`، `/assistants`

- تسجيل الدخول باسم المستخدم وكلمة المرور
- جلسات آمنة عبر cookies (مع `httpOnly`)
- عرض الملف الشخصي ونشاطات المستخدم
- للمعلم فقط:
  - إنشاء مساعدين جدد مع تحديد صلاحياتهم
  - تعديل صلاحيات المساعدين
  - حذف المساعدين
  - عرض لوحة المعلم ونشاطات المساعدين

**API endpoints:**
- `POST /api/auth/login` — تسجيل الدخول
- `POST /api/auth/logout` — تسجيل الخروج
- `GET /api/auth/me` — عرض الملف الشخصي
- `PUT /api/auth/me` — تعديل الملف الشخصي
- `POST /api/auth/assistants` — إنشاء مساعد (معلم فقط)
- `GET /api/auth/assistants` — عرض المساعدين (معلم فقط)
- `PUT /api/auth/assistants/:id` — تعديل مساعد (معلم فقط)
- `DELETE /api/auth/assistants/:id` — حذف مساعد (معلم فقط)

### ٢. لوحة التحكم

**الصفحات:** `/` (لوحة المساعد)، `/teacher-dashboard` (لوحة المعلم)، `/admin` (لوحة الإدارة)

#### لوحة المساعد (`/`)
- إحصائيات سريعة: عدد الطلاب، المجموعات، الحصص، المدفوعات
- روابط سريعة: إضافة طالب، إدارة الحصص، المدفوعات، الامتحانات، الكتب، QR code

#### لوحة المعلم (`/teacher-dashboard`)
- إحصائيات اليوم: الطلاب، المجموعات، المساعدين، حصص اليوم، دفعات اليوم، إيرادات اليوم
- قائمة المساعدين مع تواريخ انضمامهم
- آخر نشاطات المساعدين (آخر 200 نشاط)
- إنشاء مساعد جديد

#### لوحة الإدارة الشاملة (`/admin`)
- إحصائيات شاملة: إجمالي الإيرادات، إجمالي الديون، أعداد الطلاب (النشطين والكل)، المجموعات، الحصص، الموظفين
- رسم بياني شهري للإيرادات لآخر 6 أشهر

### ٣. الطلاب

**الصفحات:** `/students`، `/students/:id/dashboard`

#### قائمة الطلاب (`/students`)
- عرض جدولي مع ترقيم الصفحات
- فلترة: بحث بالاسم أو ID، المجموعة، الصف الدراسي، النوع، حالة النشاط
- إضافة وتعديل وحذف الطلاب
- تفعيل/إلغاء تفعيل الطالب
- تصدير CSV للبيانات المعروضة
- إنشاء عروض/خصومات
- مسح QR code للتنقل السريع للوحة الطالب

#### لوحة الطالب (`/students/:id/dashboard`)
- معلومات الطالب الأساسية
- إحصائيات الحضور (الحاضر، الغائب، النسبة المئوية، شريط تقدم)
- ملخص المدفوعات: المستحق والمدفوع والمتبقي للحصص والكتب، رصيد المحفظة
- قائمة المدفوعات الفردية مع إمكانية الحذف والتصدير
- النتائج: قائمة الامتحانات مع الدرجات وأشرطة تقدم
- الكتب: حجز وإلغاء حجز الكتب، تطبيق خصومات
- سجل الحضور الكامل
- طباعة QR code للطالب
- تغيير مجموعة الطالب

**API endpoints:**
- `GET /api/students` — قائمة الطلاب (مقسم)
- `POST /api/students` — إنشاء طالب
- `GET /api/students/:id` — عرض طالب
- `PUT /api/students/:id` — تعديل طالب
- `DELETE /api/students/:id` — حذف طالب
- `POST /api/students/:id/activate` — تبديل حالة النشاط
- `POST /api/students/:id/change-group` — تغيير المجموعة
- `GET /api/students/:id/dashboard` — لوحة الطالب الكاملة
- `GET /api/students/barcodes/print` — بيانات طباعة QR

### ٥. الحصص والحضور

**الصفحات:** `/sessions`، `/sessions/:id/attendance`

#### قائمة الحصص (`/sessions`)
- عرض هرمي: الصف ← المجموعة ← الشهر ← الحصص
- تصفية: إظهار النشطة فقط / عرض الكل (للمعلم فقط)
- إضافة وتعديل وحذف الحصص الفردية
- إنشاء جماعي للحصص:
  - **شهري**: تحديد شهر ومجموعة وأيام الحصص
  - **أسبوعي**: تاريخ بداية ونهاية وأيام محددة
  - **بعدد**: عدد محدد من الحصص ابتداءً من تاريخ
- تفعيل/إلغاء تفعيل الحصة (للمعلم فقط)
- حذف شهر كامل من الحصص لمجموعة
- تصدير CSV

#### الحضور (`/sessions/:id/attendance`)
- إحصائيات الحضور: العدد الكلي، الحاضر، الغائب، المعلق، النسبة
- إدخال حضور يدوي بـ ID الطالب
- مسح QR code بالكاميرا
- وضع Auto-Pay: عند مسح QR، يتم تسديد تكلفة الحصة تلقائيا من المحفظة
- إجراءات جماعية: تحديد الكل، عكس التحديد، تعيين حاضر، تعيين غائب
- فلترة العرض: الكل، الحاضر فقط، الغائب فقط، المعلق فقط
- تصدير CSV للحضور

**API endpoints:**
- `GET /api/sessions` — قائمة الحصص
- `POST /api/sessions` — إنشاء حصة
- `POST /api/sessions/bulk-create` — إنشاء جماعي (حد أقصى 50)
- `GET /api/sessions/:id` — عرض حصة
- `PUT /api/sessions/:id` — تعديل حصة
- `DELETE /api/sessions/:id` — حذف حصة
- `POST /api/sessions/:id/toggle-active` — تفعيل/إلغاء تفعيل
- `DELETE /api/sessions/month/:groupId/:year/:month` — حذف شهر
- `GET /api/sessions/:id/attendance` — عرض الحضور
- `POST /api/sessions/:id/attendance/edit` — تعديل الحضور
- `POST /api/sessions/:id/attendance/scan` — مسح QR

### ٦. المدفوعات والمحفظة

**الصفحات:** `/payments`، `/payments/:id/history`

نظام المدفوعات في طلابي متقدم ويعمل بمبدأ **المحفظة** (Wallet):

- كل طالب لديه محفظة تحسب المديونية والرصيد تلقائيا
- كل دفعة يتم توزيعها (Allocation) آليا على الحصص غير المسددة أو الكتب غير المسددة
- عند إضافة دفعة، يقوم النظام بتوزيع المبلغ على الديون المستحقة حسب تاريخها
- إذا زادت الدفعة عن المطلوب، يتحول الفائض إلى رصيد محفظة يمكن استخدامه لاحقا
- إذا نقصت، يظل المتبقي كديون على الطالب

#### قائمة المدفوعات (`/payments`)
- عرض جدولي مع ترقيم الصفحات
- فلترة: بحث باسم الطالب أو ID، المجموعة
- إظهار المديونية الكلية للحصص والكتب مع رصيد المحفظة
- إضافة دفعة سريعة من القائمة
- التنقل لسجل المدفوعات
- تصدير CSV

#### سجل المدفوعات (`/payments/:id/history`)
- إحصائيات: المبلغ المستحق، المدفوع، المتبقي/رصيد المحفظة، قيمة العرض
- جدول بكل دفعة: المبلغ، التاريخ، وقت الإضافة
- حذف دفعة فردية مع إعادة توزيع المحفظة تلقائيا

**API endpoints:**
- `GET /api/payments` — قائمة المدفوعات (مقسمة)
- `POST /api/payments/reload` — معطل (نظام قديم)
- `GET /api/payments/download-csv` — تصدير CSV
- `POST /api/payments/:studentId/add` — إضافة دفعة
- `PUT /api/payments/each/:id` — غير مدعوم
- `DELETE /api/payments/each/:id` — حذف دفعة
- `GET /api/payments/:studentId/history` — سجل المدفوعات

**لمحة عن خوارزمية التسوية (Reconciliation):**
```
1. يتم إعادة تعيين amountPaid لجميع سجلات الحضور والحجوزات إلى 0
2. يتم إعادة تعيين allocations لكل دفعة إلى []
3. يتم ترتيب الدفعات زمنيا (الأقدم أولا)
4. لكل دفعة من نوع sessions، يتم توزيع المبلغ على الحضور غير المسدد
5. لكل دفعة من نوع book، يتم توزيع المبلغ على حجوزات الكتب غير المسددة
6. أي مبلغ متبقي بعد التسوية يعتبر رصيد محفظة
7. أي دين متبقي يظهر كمديونية
```

### ١٠. الشات وواتساب

**الصفحة:** `/chat`

نظام تواصل متكامل مع الطلاب وأولياء الأمور عبر WhatsApp Business API.

#### المميزات
- **قائمة محادثات**: أحدث المحادثات مرتبة زمنيا مع عرض آخر رسالة وعدد الوارد غير المقروء
- **تبويب أشخاص**: البحث عن طالب وبدء محادثة معه أو مع ولي أمره
- **تبويب غير معروف**: الرسائل الواردة من أرقام غير مرتبطة بأي طالب
- **إرسال رسائل**: عبر واجهة شبيهة بـ WhatsApp Web مع إمكانية اختيار المستلم (ولي الأمر أو الطالب)
- **استقبال رسائل**: webhook يستقبل رسائل واتساب الواردة ويربطها تلقائيا بالطالب إذا كان الرقم مسجلا
- **حالة الرسالة**: يعرض حالة الإرسال (قيد الإرسال، مرسلة، وصلت، مقروءة، فشلت)
- **ترقيم الصفحات**: لكل الأقسام (محادثات، أشخاص، غير معروف، رسائل)
- **إشعارات القراءة**: فتح المحادثة يخفي الإشعار (دون تغيير حالة القراءة في واتساب)
- **رسائل سريعة**: قوالب جاهزة (موعد حصة، تذكير دفع، غياب، درجة جديدة)
- **تشخيص webhook**: عرض آخر الأحداث الواردة من واتساب للتأكد من عمل الاتصال
- **تسوية أرقام مصري**: تحويل تلقائي للأرقام المصرية إلى الصيغة الدولية

#### آلية عمل webhook
1. ميتا ترسل POST إلى `/api/chat/webhook`
2. النظام يسجل الحدث خام في جدول `ChatWebhookEvent`
3. يعالج حالة الرسائل (status updates) ويحدث حالة الرسالة في قاعدة البيانات
4. يعالج الرسائل الواردة: يبحث عن الطالب بالرقم، وينشئ سجل رسالة جديد

#### الأمان
- نقطة التحقق من webhook (GET) تتحقق من `WHATSAPP_VERIFY_TOKEN`
- نقطة استقبال webhook (POST) لا تحتاج مصادقة (عامة لميتا)

**API endpoints:**
- `GET /api/chat/conversations` — قائمة المحادثات (مقسمة، مع بحث)
- `GET /api/chat/conversations/summary` — إحصائيات سريعة
- `GET /api/chat/recent` — آخر الرسائل للتدقيق
- `GET /api/chat/students` — بحث الطلاب (مقسم)
- `GET /api/chat/messages` — رسائل محادثة (مقسمة)
- `POST /api/chat/messages/mark-seen` — تعليم كمقروء داخليا
- `GET /api/chat/unknown` — رسائل غير معروفة
- `GET /api/chat/webhook/events` — أحداث webhook الأخيرة
- `POST /api/chat/messages/send` — إرسال رسالة
- `GET /api/chat/webhook` — التحقق من webhook ميتا
- `POST /api/chat/webhook` — استقبال أحداث واتساب
- `GET /api/chat/webhook/debug` — تشخيص إعدادات واتساب

## التشغيل المحلي

### المتطلبات
- Node.js v18+
- npm

### 1. تنزيل المشروع
```bash
git clone <repository-url>
cd tollaby
```

### 2. إعداد قاعدة البيانات
```bash
cd backend
npm install
cp .env.example .env   # أو استخدم .env الموجود
npm run db:push        # مزامنة schema مع SQLite
npm run db:seed        # تعبئة بيانات تجريبية
```

### 3. تشغيل الخادم
```bash
# نافذة 1 — الخادم
cd backend
npm run dev            # nodemon مع إعادة تشغيل تلقائي

# نافذة 2 — الواجهة الأمامية
cd frontend
npm install
npm run dev            # Vite dev server على port 5173
```

- البريد: http://localhost:5173
- حساب معلم: `admin` / `admin123`
- حساب مساعد: `assistant` / `assistant123`

## نظام المحفظة والتسوية

نظام التسوية (Reconciliation) هو قلب المنظومة المالية في طلابي.

### مكونات النظام

1. **`backend/src/utils/payments.js`** — حاسب المديونية
   - `getOfferValue(offer)` — استخراج قيمة العرض
   - `getSessionCosts(student, attendances)` — حساب تكلفة كل حصة بعد الخصم
   - `getBookCost(booking)` — حساب تكلفة الكتاب بعد الخصم
   - `summarizeStudentPayments(student)` — ملخص ديون الطالب الكامل
   - `getStudentPaymentSnapshot(prisma, studentId)` — لقطة كاملة من DB

2. **`backend/src/utils/wallet.js`** — موزع المدفوعات
   - `reconcileStudentPayments(prisma, studentId)` — إعادة تسوية طالب واحد
   - `reconcileManyStudents(prisma, studentIds)` — إعادة تسوية عدة طلاب
   - `applyUnallocatedBalance(prisma, studentId)` — توزيع الرصيد غير المخصص
   - `refundAttendance(prisma, studentId, attendanceId)` — استرداد مبلغ حصة
   - `refundBookBooking(prisma, studentId, bookingId)` — استرداد مبلغ كتاب

### متى تتم التسوية؟

تتم التسوية تلقائيا عند:
- إضافة دفعة جديدة
- حذف دفعة
- تعديل بيانات الطالب (تغيير المجموعة، العرض)
- تعديل حصة (تغيير السعر، المجموعة)
- حذف حصة
- مسح حضور مع auto-pay
- حجز/إلغاء حجز كتاب
- حذف كتاب
- تعديل خصم كتاب

### مثال عملي

```
الطالب لديه:
- حصة 1: 100 ج
- حصة 2: 100 ج
- الكتاب X: 50 ج

يدفع: 150 ج → نوعها sessions
التوزيع:
  - الحصة 1: 100 ج ← مدفوعة
  - الحصة 2: 50 ج ← باقي 50 ج
  - الكتاب X: 0 ← لم يمس

يدفع لاحقا: 80 ج → نوعها sessions
  - الحصة 2: 50 ج ← مدفوعة
  - رصيد المحفظة: 30 ج

يدفع: 50 ج → نوعها book
  - الكتاب X: 50 ج ← مدفوع
```
